# Super Admin service health and Android alarms

The database samples aggregate traffic once per minute. The visible Super Admin dashboard refreshes its traffic panel every 30 seconds, shows eight alerts per page, and retains seven days of samples and 30 days of resolved alerts. It reports database transactions, fetched rows, rollbacks, overdue queues, route usage, and likely write-heavy tables. An alert resolves when its signal recovers; acknowledgement is per admin. A sample older than three minutes is marked stale.

The spending panel estimates today's margin from collected completed rides, settlement and referral provisions, published provider rates, recorded charges, and app-observed usage. At or below an **estimated 10% margin**, optional route checks switch to savings mode automatically; the manual savings switch remains available. Paid Google Route Matrix calls are also constrained by today's earned operating allowance after a 5% target profit provision. The Google free allowance is monthly and shared across the billing account, so the app's project ledger is an approximation. Provider invoices, all Supabase usage, and calls from other Google projects are not fully observable here. Reconcile the estimate with provider billing before treating it as actual profit.

The **Enable alarm** button enables a six-second browser siren while the dashboard is visible. It sounds for active traffic spikes and for the estimated 10% margin warning. Browser audio stops when the page is hidden; Android phone alerts use a separate native path.

Android version 1.0.11 adds an inexact idle-capable alarm check to the existing WorkManager fallback. Install the signed APK from `/download`, sign in as Super Admin, open **Service health**, enable phone alerts, and allow Android notifications. **Last server check** shows whether this phone has actually reached the alarm endpoint. **Test phone alarm** schedules a local notification about ten seconds later so the admin can lock the screen and check the sound; it does not test remote delivery. **Sound settings** opens Android's channel controls. The phone stores a random credential encrypted with Android Keystore and checks the private `admin-alarm-poll` endpoint around every 15 minutes when Android permits. The six-second siren is bundled in the APK under [CC0](../android/ALARM_SOUND_LICENSE.md). Server polling verifies that the phone's owner still has Super Admin access; disabling alerts or signing out stops polling and revokes the credential. The retired Firebase sender cron and queue trigger are disabled.

Android's scheduled checks remain inexact: Doze, battery saving, no network, notification settings, or force-stop can delay or prevent a screen-off alarm. Recently resolved **critical** spikes remain eligible for phone delivery for one hour, so a brief incident can still sound at the next successful check; a resolved warning does not. This is a low-cost monitoring aid, not guaranteed instant paging. One enabled phone can make roughly 96–192 checks per day depending on whether the two schedulers overlap; bounded retries and app opens may add a few more.
