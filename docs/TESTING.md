# Automated testing

Run the front-end interaction tests with `npm test`. They render the application in a DOM and exercise Operations partner setup/assignment, partner delivery/POD actions, customer tracking/notifications/payment information, Finance job costs/receipts/settlements, BDO lead workflows, and Warehouse role routing. Supabase client calls are mocked in these tests, so they check frontend behavior, not database authorization.

Run database integration tests with `npm run test:db:linked` after applying the migrations to the linked Supabase project. This runs each SQL integration test against that project. Each test wraps fixtures in a transaction and rolls them back. Notification coverage checks membership fan-out and private inbox access; finance coverage checks receipt/settlement workflows, caps and margin math, role access, and customer-only receipt visibility; Business Development coverage checks assignment, conversion, activity access, reports, and manager-only partner approval; Warehouse coverage checks receipt, reservation, per-line picking, packing, Operations release, delivery-time stock consumption, cancellation, and role access. Parcel and route tests cover job parcel creation, route assignment, and route constraints. The database assigns sequence values outside transaction rollback, so these test runs can create gaps in generated business reference numbers without leaving fixture rows.

Run the full release gate with `npm run verify`. It runs front-end tests, lint, production build, then linked-database integration tests. The feature reviewer independently checks the change and reports findings before a phase is marked complete.
