# Kwik-Parsel Android app

Version 1.0.4 adds an opt-in reboot receiver. The rider must first start tracking in the app and grant Android's **Allow all the time** background-location permission using **Allow location after reboot**. After reboot the app attempts to restart visible sharing **off duty**, so a reboot cannot silently make the rider dispatch-eligible. Android may still block the restart, and force-stop prevents it until the rider opens the app. The position-only grant is renewed near expiry while authorized fixes arrive; revoked access is never renewed. The rider can stop sharing in the app or notification. See the linked rider location terms. Test reboot, locked-screen tracking, off-duty sharing, revoked permission, expired grant and force-stop on a real phone before relying on this for safety.

`android/` is a native Android WebView for the live site. It uses the existing Kwik-Parsel icon and registers verified links for `https://gohezoh-services.vercel.app/`. The native bridge is restricted to the site's main frame. Other destinations open outside the app.

When a rider taps **Go online**, the site issues a random, position-only tracking grant. The Android foreground service then obtains phone GPS updates and posts them directly to Supabase while the screen is off. It uses the same 100-metre accuracy gate and current-position table as browser tracking. The service does not receive the rider's password, access token, or refresh token. It displays a persistent on-duty notification with a **Go offline** action. Signing out, revoking rider access, or the grant's 16-hour expiry ends reporting. Android may still stop a service under extreme battery restrictions or if the rider force-stops the app; a stale position expires server-side.

The app must be installed as an APK before a website link can open it. Android verifies the association using [`public/assetlinks.json`](../public/assetlinks.json), served at `/.well-known/assetlinks.json` through a Vercel rewrite, and the release signing certificate. The signing key and password stay locally in ignored `android/release-signing-v2.jks` and `android/signing.properties`; they must be backed up securely before distributing the APK. A new signing key requires an update to `assetlinks.json`, then a website deployment, before links will verify again. If Google Play App Signing is adopted, add its app-signing SHA-256 fingerprint to the asset links file.

Build prerequisites: JDK 17, Android SDK Platform 36, and SDK Build Tools 35.0.0 or newer. Put the site's public `VITE_SUPABASE_PUBLISHABLE_KEY` in the root `.env.local` or the build environment. From `android/`, run `./gradlew assembleRelease` (or `gradlew.bat assembleRelease` on Windows). The signed APK is `android/app/build/outputs/apk/release/app-release.apk`. Install it on a phone, allow precise location, tap **Go on duty**, then lock the screen and verify that the visible location-sharing notification remains. **Go off duty** stops dispatch matching while the foreground service continues sharing a fresh GPS fix with the rider's own company and customers with paid, active deliveries; **Stop sharing location** ends tracking. No server can request a new fix when the phone has no internet, GPS is disabled, the service is stopped or killed, or its tracking grant expires. Browser tracking still pauses when the page is hidden.

After installing the signed APK, check Android's link verification with `adb shell pm verify-app-links --re-verify org.gohezohservices.kwikparsel` and `adb shell pm get-app-links org.gohezohservices.kwikparsel`. The asset links file must be served as JSON at `https://gohezoh-services.vercel.app/.well-known/assetlinks.json` without a redirect. Tested links should launch the installed app; without installation they continue to open the website.
