# Kwik-Parsel Android app

Version 1.0.9 adds a Super Admin service alarm without Firebase. After signing in as Super Admin, open **Service health**, turn on phone alerts, and allow Android notifications. The app stores a random device credential encrypted with Android Keystore. WorkManager checks for new traffic spikes and a server-estimated profit margin at or below 10% about every 15 minutes, even with the screen off. Each new incident produces one high-priority notification with vibration and the bundled [CC0 alarm sound](../android/ALARM_SOUND_LICENSE.md). Android battery saving, Doze, offline state, disabled notifications and force-stop can delay or prevent an alert; this is a monitoring aid, not a guaranteed instant paging service. Signing out or disabling phone alerts stops checks and revokes the device credential. Install the new APK to get native alarms; a website update alone cannot add this background behavior.

Version 1.0.6 changes the off-duty request check to once an hour. A pending request remains valid for 70 minutes to cover the next check and GPS/network delay. On-duty GPS reporting is unchanged. Riders must install the new APK; a website update alone cannot change the native check interval.

Version 1.0.5 introduced on-demand off-duty location. The visible Android service checks for authorized requests without requesting GPS updates or writing positions between requests. Once asked, it obtains a fresh fix and sends one position. On-duty dispatch tracking remains continuous. Requests can take up to an hour plus GPS acquisition and network delay; disconnected or force-stopped phones cannot respond. The company and eligible customer screens display a pending request and then a timestamped fix. The polling read still has a database cost; it replaces frequent off-duty position writes.

Version 1.0.4 added an opt-in reboot receiver. The rider must first start tracking in the app and grant Android's **Allow all the time** background-location permission using **Allow location after reboot**. After reboot the app attempts to restart its visible service **off duty**, so a reboot cannot silently make the rider dispatch-eligible. Android may still block the restart, and force-stop prevents it until the rider opens the app. The position-only grant is renewed near expiry while authorized fixes or off-duty request checks arrive; revoked access is never renewed. The rider can stop sharing through the Android notification or phone permission controls. Test reboot, locked-screen tracking, off-duty requests, revoked permission, expired grant and force-stop on a real phone before relying on this for safety.

`android/` is a native Android WebView for the live site. It uses the existing Kwik-Parsel icon and registers verified links for `https://gohezoh-services.vercel.app/`. The native bridge is restricted to the site's main frame. Other destinations open outside the app.

When a rider taps **Go on duty**, the site issues a random, position-only tracking grant. The Android foreground service then obtains phone GPS updates and posts them directly to Supabase while the screen is off. It uses a 100-metre accuracy gate and a current-position table. The service does not receive the rider's password, access token, or refresh token. It displays a persistent notification. Signing out or revoking rider access ends reporting. Android may still stop a service under battery restrictions or if the rider force-stops the app; a stale position expires server-side.

The app must be installed as an APK before a website link can open it. Android verifies the association using [`public/assetlinks.json`](../public/assetlinks.json), served at `/.well-known/assetlinks.json` through a Vercel rewrite, and the release signing certificate. The signing key and password stay locally in ignored `android/release-signing-v2.jks` and `android/signing.properties`; they must be backed up securely before distributing the APK. A new signing key requires an update to `assetlinks.json`, then a website deployment, before links will verify again. If Google Play App Signing is adopted, add its app-signing SHA-256 fingerprint to the asset links file.

Build prerequisites: JDK 17, Android SDK Platform 36, and SDK Build Tools 35.0.0 or newer. Put the site's public `VITE_SUPABASE_PUBLISHABLE_KEY` in the root `.env.local` or the build environment. From `android/`, run `./gradlew assembleRelease` (or `gradlew.bat assembleRelease` on Windows). The signed APK is `android/app/build/outputs/apk/release/app-release.apk`. Install it on a phone, allow precise location, tap **Go on duty**, then lock the screen and verify that the visible location-sharing notification remains. **Go off duty** stops dispatch matching and continuous GPS reporting, while the service checks for authorized requests hourly. No server can request a new fix when the phone has no internet, GPS is disabled, the service is stopped or killed, or its tracking grant expires. Browser tracking still pauses when the page is hidden.

After installing the signed APK, check Android's link verification with `adb shell pm verify-app-links --re-verify org.gohezohservices.kwikparsel` and `adb shell pm get-app-links org.gohezohservices.kwikparsel`. The asset links file must be served as JSON at `https://gohezoh-services.vercel.app/.well-known/assetlinks.json` without a redirect. Tested links should launch the installed app; without installation they continue to open the website.
